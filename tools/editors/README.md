# 内容编辑器操作手册

本工具以独立桌面程序编辑地铁线路图、客户/NPC、对话事件线和站点探索地图。程序及内部内容服务共用 `tools/editors/`；Godot 轻量启动器位于 `Game/addons/metro_content_editor/`，操作同一份 `Game/`。

## 1. 启用 Godot 启动入口

1. 用 Godot 4.7.2 打开 `Game/project.godot`。
2. 在 **项目 → 项目设置 → 插件** 启用 **Metro 内容编辑器**（仓库默认启用）。
3. 在右侧 **Metro内容编辑器** 面板点 **打开独立编辑器窗口**，或用“项目 → 工具 → Metro 独立内容编辑器”。
4. 编辑器打开为独立桌面程序窗口，不占用 Godot 主编辑区，不调用系统浏览器，也没有浏览器地址栏或标签页。窗口内部使用 Qt 的界面控件承载原有完整编辑界面。
5. 程序自动识别当前游戏项目和 Godot 可执行文件，建立并保存双向路径。正常使用无需手填项目路径、编辑器目录或端口。
6. 可勾选 **打开项目时自动启动**。该选项按 Godot 项目保存，下次打开同一项目会自动打开程序；程序已经运行时只唤起已有窗口。

Godot 插件只保留启动、偏好和资源刷新。所有地图、客户、剧情、关卡及目录编辑均在独立窗口内操作；Godot 与程序互不强制关闭，关闭/禁用 Godot 插件不会丢弃独立窗口中未保存的内容。

### 首次安装桌面依赖

需要 **Python 3.10+、Pillow、PySide6**。在仓库根目录执行：

```sh
python -m pip install -r tools/editors/requirements-desktop.txt
```

Godot 右侧面板的“启动设置”默认开启“自动查找并填充启动路径”，启用插件时和运行期间都会自动填入当前有效的 Python 路径，依次检查仓库根目录 `.venv-editor`、`.venv`、`tools/editors/.venv`，然后检查 PATH；Windows 还会检查当前用户和 Program Files 下的标准 Python 安装目录。Windows 使用环境内的 `Scripts/python.exe`，其他系统使用 `bin/python`。自动模式下路径栏只读，显示实际采用的地址；项目、Godot、编辑器目录和服务地址同时显示在启动设置中。取消自动模式后，可手填可信解释器覆盖自动选择，支持完整路径或相对仓库根目录的路径（例如 Windows 的 `.venv-editor/Scripts/python.exe`）。如果保存的路径已失效，插件初始化或启动时会恢复自动模式、清除旧覆盖值并重新查找和填充，不需要用户先清空。自动探测结果另行缓存，不会变为锁定旧机器地址的手动覆盖值。正常目录保持仓库下 `Game/` 与 `tools/` 并列即可。

推荐在每台电脑的仓库根目录执行一次（Windows）：

```powershell
py -3 -m venv .venv-editor
.\.venv-editor\Scripts\python.exe -m pip install -r tools/editors/requirements-desktop.txt
```

macOS / Linux 对应命令：

```sh
python3 -m venv .venv-editor
.venv-editor/bin/python -m pip install -r tools/editors/requirements-desktop.txt
```

报错 `Could not create child process` 时，先核对错误中的 Python 路径与当前仓库位置。如果仍指向旧目录，新版插件会自动重新查找、填入当前路径；也可点击“重新查找并关联”立即刷新。若当前环境不存在，使用上面的命令在新目录重建；若文件存在但仍无法启动，也应重建环境，以排除虚拟环境内部记录的旧 Python 安装位置。`godot-ai` 的 MCP 警告不属于内容编辑器启动错误。

虚拟环境不提交，也不要跨电脑复制；在各电脑重建后，保留默认自动模式即可，无需填写启动路径。自动查找不会安装依赖。

也可直接双击 `启动内容编辑器.cmd`，或运行：

```sh
python tools/editors/desktop.py --project /path/to/Game
```

### 窗口与保存

桌面程序具有自己的菜单、最大化/最小化、窗口尺寸记忆和退出行为；导入素材使用系统文件选择器。

保存以**当前编辑项**为单位，无需每改一个属性就保存：

| 编辑项 | 一次保存包含 |
| --- | --- |
| 线路地图 | 线路层、贴图层、全部结点与地图素材变换 |
| 站点关卡 | 当前站点的街道、地图格、建筑实例、怪物、NPC 与物资生成点 |
| 物品 / 建筑模板 / 怪物 | 当前选中的一条定义及其贴图、占位、碰撞、掉落等全部属性 |
| 顾客 | 当前顾客资料、商品配置及所有见面对话与事件线 |
| 总设置 | 当前 Godot 接口配置 |

保存草稿按钮固定在窗口右下方，宽度285像素（较原先加长50%）：有未保存改动时为红色，未检测到改动时为绿色并显示“已保存”。可在同一项内连续调整，最后点击红色“保存草稿”、菜单“文件 → 保存当前编辑”或按 **Ctrl+S**（macOS 也支持 Cmd+S）。关卡内“编辑此建筑”及室外物资点属于该关卡的子编辑界面；点“返回关卡”自动合入当前草稿，不要求先保存细节，最终保存一次关卡即可。目录里的建筑模板则是独立编辑项。

切换条目、切换编辑类别、更换站点、重新读取地图、关闭或刷新桌面窗口时，若当前项有未保存内容，会弹出三项选择：

- **保存并离开**：保存整个当前项，成功后才切换或关闭。
- **放弃修改**：恢复当前项进入时或最后保存时的内容，再离开。
- **取消**：保留当前界面和全部修改，继续编辑。

校验或写入失败时保留草稿和提示框，不执行切换。重复点击当前条目不会重载草稿；切换网格、贴图预览或同一顾客内的对话节点不要求单独保存。删除/归档目录条目也先成为当前项修改，保存后生效。Godot 预览会先保存当前关卡。

同一个 Game 只启动一个桌面窗口。再次从 Godot 或命令行启动会激活已有窗口。退出窗口会清理自己的内容服务及连接文件，不关闭 Godot。停止 Godot 不强制结束这个独立程序。

### 文件管理器与旧入口

双击 `启动内容编辑器.cmd` 或 `编辑器（程序端）.cmd` 都打开独立程序窗口；原浏览器启动脚本已更名。直接运行 `python tools/editors/server.py` 也转入程序窗口，不再自动打开浏览器。

`server.py --no-browser` 仅保留给自动测试与接口调试，不作为普通使用入口。程序内的完整地图、客户、物品与建筑界面仍共用原有模块。

可选 Windows EXE 构建见 [打包说明](../build/README.md)。

## 2. 自动双向路径与复用结构

| 本机配置 | 内容 |
| --- | --- |
| `Game/content/editor-settings.local.json` | `project` 当前游戏路径、`editor_root` 编辑器目录、当前 `godot_executable`、`integration:desktop/browser`、两个服务的会话信息 |
| `tools/editors/.projects.local.json` | `active_project` 最近使用的游戏，以及按项目保存的双向路径 |
| `Game/.godot/metro_editor_connection.json` | 当前独立程序的本机地址、进程号、协议版本及窗口类型 |
| `Game/.godot/metro_browser_connection.json` | 自动测试/调试服务的本机地址、项目、会话与运行时路径 |
| `Game/.godot/metro-editor/window.ini` | 桌面程序的窗口尺寸/位置 |
| Godot 项目元数据 | 自动启动选项、非默认 Python 路径 |

这些配置均不提交到远端。协作者下载后首次打开程序会生成自己机器上的路径；移动仓库后再次从 Godot 启动会自动更新。共享服务的 `register_project()` 是双向路径的唯一写入实现，保留原有设置字段，避免两端重复维护写入规则。

“总设置 / Godot”可查看项目与引擎路径；从独立编辑器打开 Godot、运行游戏和预览关卡时使用自动记录的引擎。Godot 面板的“刷新 Godot 工程资源”直接调用引擎资源扫描；通常切回 Godot 后引擎也会自行发现文件变化。

### 自动查找与双向关联

启用 Godot 插件后，每两秒读取当前项目的连接记录。独立程序或 Godot 任一端先启动均可关联，无需开启“自动启动”。Godot 核验 `/api/bridge` 中的协议、项目和会话后，通过带编辑令牌的 `/api/link` 回写实际运行的 Godot 路径。面板显示服务地址及双方路径；“总设置”显示期间每两秒自动更新，正在输入的手动修改不会被覆盖。临时连接失败可点“重新查找并关联”。

内部服务仍保留兼容旧会话和自动测试的协议。退出后保留的路径需要核验实际服务才会关联；移动项目后重新启动程序会更新地址。

### 风险和实现边界

本功能只读取已知项目内的连接文件并访问 `127.0.0.1`，不扫描全盘、局域网，不接受 HTTP 重定向。路径和会话检查能避免误连另一个项目；它们不是抵御本机恶意软件的身份认证机制。具有当前用户文件权限的程序仍可伪造连接记录，因此只应使用可信项目及本机程序。

自动关联只登记路径，不自动执行对端报送的 Python 或项目外脚本。点击“打开独立编辑器窗口”才使用项目环境 / PATH / 手动指定的解释器运行仓库内工具。**自动执行任意外部编辑器路径可能以当前用户权限运行恶意代码**，本次未开放该行为。若将来需要此功能，建议增加逐个路径的显式信任授权。程序中的“打开 Godot / 预览”属于用户主动执行操作，所填 Godot 路径也应可信。

### 地铁地图编辑：线路层 / 贴图层

点击顶部 **地图编辑**。这里编辑地铁总线路图；“站点与关卡”继续编辑站点内部探索街区。

| 图层 | 鼠标操作 |
| --- | --- |
| 线路层 | 点击线路色卡选择线路；拖动站点圆点或折点调整位置。站点位置由所有经过它的线路共用 |
| 插入折点 | 选择“插入折点”，点击目标线段；选中后可拖动、删除 |
| 追加结点 | 点击空白处追加折点，点击已有站点接入该站；再次选择“选择 / 拖动”结束追加 |
| 新增站点 | 选择工具后点击位置，自动追加到当前线路；侧栏可修改未保存新站的名称、坐标及文字偏移 |
| 增删线路 | “＋ 线路”新建后追加至少两个结点；“－ 当前线路”删除整条线路；支持撤销 |
| 删除结点 | 选中当前线路上的站点或折点，点删除按钮或 Delete，从该线路移除。已有游戏站名保留，避免使存档与关卡引用失效；站点不再连接的线路也不再可通行 |
| 贴图层 | 导入 PNG 地图素材或从现有素材添加；拖动移动，拖右下角紫色方块缩放。侧栏调整位置、尺寸、旋转、透明度和显示状态 |
| 贴图顺序 | “上移一层 / 下移一层”改变贴图层内的覆盖顺序；所有运行线路和站点仍绘制在贴图之上 |

滚轮缩放，中键或右键拖动画布，Ctrl+Z 撤销；“适应画布”恢复全图。两层始终使用相同地图坐标，切换图层只改变可编辑的对象。原河流与非运行参考线已保存为独立 `assets/maps/network_base.png`，可在贴图层调整、隐藏或替换；五条运行线路保留为可编辑节点。

点“保存地图”或顶部“保存当前编辑”写入 `content/network_map.json`，并同步站点列表。折点只改变线路形状；同一线路内相邻**站名节点**决定行车连接，首尾同站构成环线。仅含折点的参考线路不产生行车连接。每条线路保存时至少两个节点；不能重复经过同一站（首尾闭环除外）。游戏耗电与可达路径使用修改后的连接。

重进该页保留未保存草稿；“重新读取”会提示是否丢弃草稿。多窗口基于内容版本检查，过期窗口无法覆盖较新的地图，需要重新读取后继续修改。

### 地图数据与对接接口

`GET /api/bridge` 返回 `protocol:metro-editor`、`version:1`、工程路径、图层与资源路径，供 Godot 验证是否连接正确工程。`GET /api/network-map` 返回 `{definition,revision}`；`POST /api/network-map` 发送同结构，写入仍需 `X-Editor-Token`。`revision` 不匹配时拒绝写入并保留磁盘新版本。`POST /api/network-image` 接收 `{id,data}` 的 PNG Data URL，保存独立素材到 `assets/maps/`。这些接口仅监听本机。

地图定义格式为：

```json
{
  "version": 1,
  "canvas": {"width": 1500, "height": 1150},
  "stations": {"示例站": {"position": [200, 100], "label": [10, -20]}},
  "lines": [[99, "aabbcc", [[100, 100], "示例站", [300, 100]]]],
  "textures": [{"id": "map_image", "texture": "res://assets/maps/map_image.png", "position": [0, 0], "size": [1500, 1150], "rotation": 0, "opacity": 1, "visible": true}]
}
```

上例仅展示结构；实际保存必须保留已有游戏站名。`rotation` 为角度，围绕贴图左上角旋转，`position/size` 使用地图坐标。Godot 的 `scripts/content/network_catalog.gd` 将坐标对转为 `Vector2`，`cabin_map.gd` 据此绘制、命中站点及计算线路，`map/metro_map.gd` 打开时刷新；不再从 GDScript 常量反向解析编辑器地图。

## 3. 新增或修改客户/NPC

1. 点击左侧头像卡选择角色，或点击“新增顾客”。为新角色填写唯一 ID 和名称。ID 使用小写英文字母开头，后接小写字母、数字、下划线或短横线，最长64字符。
2. 填写基础预算、出现权重和阵营：红、黄、蓝、无阵营。
3. 勾选“启用”和“参加交易”，配置顾客购买/出售的商品类别。方向以顾客为准：**购买＝从玩家买，出售＝卖给玩家**。不参加交易的探索 NPC 可以不配置买卖类别。
4. 上传 PNG，或填写工程内已有的 `res://assets/...png` 路径。导入后检查左侧预览。
5. 编辑角色剧情后，点击“保存顾客和剧情”或顶部保存按钮。成功后角色出现在目录中。

| 属性 | 规则 |
| --- | --- |
| 基础预算 | 新订单的初始预算，0～1,000,000；不改变已生成订单的预算 |
| 权重 | 0～100,000；在当前站点、买卖方向的有效候选中归一化，0表示不抽取 |
| 启用、参加交易 | 控制交易候选；探索是否出现由关卡中的 NPC 放置决定 |
| 角色 ID | 作为剧情、关系和地图引用使用；保存后在界面锁定，新增角色不能覆盖已有 ID |
| 目录顺序 | 新角色追加保存，避免旧订单索引错位；停用替代删除 |

上传保留独立原图 `Game/assets/source/customers/editor_<id>.png`，并裁去透明边缘、最近邻缩放到独立48×80运行图 `Game/assets/textures/customers/editor_<id>.png`。交易窗口裁取上方48×44显示上半身；探索使用全身。角色目录在 `Game/content/customers.json`，不需要手改 `customer_catalog.gd` 注册新角色。

### 交易中的出现规则

顾客一天最多进入交易窗口一次，跨站去重。站点每日上限为邮电新村4、四平路6、同济大学5，其他站依设施分组；实际人数还受当天未到访的有效角色数量限制。“送客”也消耗此次到访，日结后恢复。关闭交易、编辑内容或读档不会重抽仍在等待的订单。

## 4. 单次见面中的多轮对话

每个事件卡封装一次完整见面，包含多句 NPC 发言、多次玩家回答和分叉；不是一个事件只能说一句话。上方跨日事件线保留，点击某次见面后，下方自动显示该次对话视窗与节点图。

1. 点击“＋新增见面对话”，填写稳定 ID、标题、优先级和互动场景（交易/探索/两者）。勾选“仅触发一次”表示整个存档完成一次；取消后可在后续会面触发，同一天同种互动内已完成的故事不重复。
2. 在对话视窗直接修改 NPC 气泡文字，或在选中节点的文本框输入。支持换行；点击“＋ NPC 连续发言”增加一轮连续发言，已有玩家回答会移到新发言之后。
3. 点击“＋ 玩家回答与下一轮”，同时创建一个玩家回答与后续 NPC 发言。直接修改右侧玩家气泡和后续 NPC 气泡文字。继续添加，可组成多轮问答。
4. 点击已有气泡或图中节点返回某一轮，再添加另一条玩家回答，就会形成分叉。节点属性仍可编辑说话人、标记、效果和分支可见条件。
5. 拖动节点排列；从右侧圆形输出端点拖到目标节点连接。粉色端点是玩家回答，青色端点是 NPC 继续发言；也可点“连接下一轮”或分支的“连到”按钮，再点目标节点。“以此轮结束”清除默认后续，分支中的“以此回答结束”清除该回答的后续。
6. “从头预览”重置对话视窗；点击下方回答按钮体验分叉。预览显示所有回答，便于检查条件分支，不修改游戏进度或关系值。
7. 使用“设为起点”“整理节点”“重命名”“删除节点”维护图，最后保存角色。选择目标“结束”或没有后续时结束本次见面；无出口循环和不存在目标会阻止保存。

当多个故事条件满足时按优先级处理。交易顾客抵达后先对话，剧情未结束前不能确认交易。节点进入效果每次会面执行一次，循环返回、恢复对话或保存读档不会重复累加。

## 5. 好感度、阵营信任与跨日事件线

♥ 好感度属于当前 NPC；◆ 信任度属于其阵营，同阵营 NPC 共享该值。二者初始0、范围 -100～100；无阵营角色不累加信任。节点与分支的变化值会保留到后续对话和日期。

上方“跨日事件线”以故事为单位显示事件框，太阳/月亮和虚线箭头标识跨日关联，♥/◆显示阈值与节点效果汇总；分支效果在各选项中查看。点击事件框切换到对应故事，下方节点图用于本次见面内部的跳转。

### 示例：第二天在探索中继续第一次交易的剧情

1. 创建红阵营 NPC，添加交易剧情 `first_meeting`。让一个节点增加好感10、阵营信任5，并设好结束路径，保存。
2. 新增故事 `followup`，互动场景选择“探索”。
3. 在“跨日继承与触发”选择前置 NPC、前置事件 `first_meeting`，间隔天数填1，点击“添加事件依赖”。跨 NPC 关联前先保存前置角色和故事。
4. 将最低好感度设为10、最低阵营信任设为5，编辑后续节点并保存。
5. 在关卡页放置该 NPC 并保存。游戏中完成第一次交易对话、休息进入下一天，再探索该关卡，靠近 NPC 按 E 触发后续。

间隔0天允许当天后续，1天表示最早下一天；多个前置事件必须全部满足。只进入节点但未完成故事，不算完成前置事件。可在关联列表中移除依赖。对应的数据结构为：

```json
{
  "id": "followup",
  "name": "再次见面",
  "contexts": ["exploration"],
  "once": true,
  "after": [{"npc": "scavenger", "story": "first_meeting", "days": 1}],
  "conditions": {"affection_min": 10, "trust_min": 5},
  "start": "greeting",
  "nodes": {
    "greeting": {"text": "又见面了。", "effects": {"affection": 2, "trust": 1}}
  }
}
```

### 条件字段

触发条件与分支条件是 JSON 对象，按“并且”组合，`{}` 表示无条件。最低好感/信任优先使用界面输入框；条件 JSON 可配置其他字段。

| 字段 | 含义 |
| --- | --- |
| `day_min` / `day_max` | 游戏日期范围 |
| `account_min` / `account_max` | 账户余额范围 |
| `debt_min` / `debt_max` | 欠费范围 |
| `completed_min` | 当前站当天最低成交数 |
| `stations` | 可触发的站名数组 |
| `has_items` | 物品 ID 到最低数量的映射，统计背包与柜子 |
| `flags_all` / `flags_none` | 必须已设置/尚未设置的标记数组 |
| `blackout` | 是否停电，布尔值 |
| `affection_min` / `affection_max` | 当前 NPC 好感范围 |
| `trust_min` / `trust_max` | 当前 NPC 阵营信任范围 |
| `events_all` | 已完成的 `npc_id/story_id` 数组 |

“进入时设置标记”使用逗号分隔，后续节点或故事可通过 flags 条件读取。`after` 额外记录前置故事完成后的天数，`events_all` 只检查是否完成。

## 6. 关卡地图编辑

### 地图选站

点击“在线路图上选择站点”，在地图直接点站点打开关卡。线路与坐标取自游戏共用的 content/network_map.json；金色是当前编辑站，青色外圈表示已有探索关卡。支持滚轮缩放、拖动空白区域平移、站名搜索定位和“适应全图”。编辑页左侧和地图标题始终显示当前站名，标题同时显示所属线路。

未登记关卡时提供邮电模板。“从邮电新村模板新建”重置编辑区，保存前不覆盖工程。关卡名称、段宽、地面 Y 和楼层高度在属性区精确调整。

### 格子和街道增减

- 点击地图格选中街道与格子，金色边框表示选中位置；双击格子重命名。
- “＋当前街道格子”只在选中街道末尾追加一格；“－选中格子”移除该格，后面的对象前移。各街道可以不等长。
- “＋街道”在选中街道之后插入一条街道，初始一格；“－选中街道”删除该街道。相邻街道连接巷口会按新索引和共同宽度调整。
- 当前限制为1～8条街道、每条1～8格，不能删除最后一条街道或街道的最后一格。
- 街道起点可以不同。选中街道后输入“街道起点”，或用成对的“－起点/＋起点”按吸附步长调整；也可在首格的 ↔ 处拖动整条街。建筑、车辆、NPC 和怪物会一起平移，巷口限制在相邻街道的重叠区。
- 删除格子会删除与该格相交的建筑及其室内物资、格子中的其他对象；删除街道会删除该街道对象。本站入口会保留或移到有效街道。“撤销地图修改”可恢复最近30次地图操作，保存/切站后重新建立撤销历史。

### 拖入和调整对象

1. 从顶部固定素材栏拖建筑卡片、站口、巷口、汽车、NPC 或怪物 到实际存在的地图格。也可点素材卡后，再点地图放置；“选择/移动”返回选择模式。
2. 建筑素材使用独立的 BuildingDefinition 类。每次拖入生成唯一实例 ID，保留素材类 ID，互不修改模板。默认提供沿街商店、居民楼、维修工坊、办公楼。
3. 点场景内建筑选中后，在属性面板修改名字、宽度、楼层和墙色，再“应用对象属性”。点击“＋选中建筑存为素材卡”保存自定义素材到 `Game/content/building_templates.json`，以后可在其他站点重复拖入。
4. 直接拖动场景内对象移动，支持跨街道；打开“栅格吸附”按指定步长对齐，关闭后自由拖动。Esc 退出放置/连接模式，Delete 可删除选中对象。
5. 建筑支持1～8层，通过专用建筑编辑中的按键增减并调整地板位置；移动、改 ID、街道及层数会同步处理其室内物资，删除建筑也删除其内部物资。
6. 巷口必须位于两条相邻街道共同存在的横向范围，物体必须在所在街道边界内。建筑太宽时需缩小或放在更长的街道。
7. 使用“预览地图”检查布局，确认后点击“保存并生成场景”。完整地图 JSON 保留在高级折叠区。

尺寸限制：每段宽256～1600、地面 Y 为200～480、楼层高度50～130、吸附步长5～200世界像素。关卡必须有本站入口/撤离口；室内物资的建筑/楼层引用必须存在。物资在建筑柜子内按点位配置的概率和权重生成，不再单独放置。

### 放置探索 NPC

先在“客户与剧情”保存角色，并将相应故事的互动场景设为“探索”或“两者”。再把关卡顶部对应 NPC 的卡片拖到目标街道，或先点 NPC 卡再点目标格，最后保存关卡。

地图只保存 NPC 身份与室外位置，例如 `{"npc":"scavenger","row":2,"x":330}`；贴图、名字与互动剧情均从角色目录读取。`row` 从0开始，同一关卡不能重复放置相同 NPC。运行时靠近按 E 交谈；暂无新剧情时显示提示。对话阻止移动，但探索时限继续。

### 预览与生成文件

| 操作 | 行为 |
| --- | --- |
| 预览地图 | 打开当前布局的网页预览，不写入关卡文件 |
| 保存并生成场景 | 校验并写入关卡 JSON、探索 tscn 和站点登记 |
| 在 Godot 中预览 | **先保存当前关卡**，再启动该站点的独立探索会话；需先配置 Godot |

生成位置：

- `Game/content/levels/station_<hash>.json`：地图与对象配置。
- `Game/scenes/exploration/stations/station_<hash>.tscn`：继承基础 `exploration.tscn` 的关卡场景。
- `Game/content/registry.json`：站点到上述配置与场景的映射。

Godot 预览使用独立的 `user://content_preview/session_<timestamp>.json`，不读取或覆盖玩家栏位。主游戏重新进入该站探索后读取新配置。邮电新村、四平路、同济大学默认共用邮电模板，保存某站会为其建立独立定义；未登记站点仍使用简化探索。

## 怪物、物品与建筑目录

三个目录都支持卡片选择、＋新建、保存、－删除（归档）、显示已删除条目与恢复。归档保留稳定 ID 和旧存档引用，不直接抹掉正在使用的配置。顾客也补充了删除/恢复；见面对话、节点、回答、依赖、地图格、街道、场景对象、建筑素材、柜子点位及掉落候选均提供对应增减操作。

### 怪物编辑与布置

“怪物”页编辑：

- 素材：PNG 横向帧条、帧数/帧率、原图朝向、显示尺寸、碰撞宽高。可从临时素材库点击选择，或导入自己的 PNG。
- 行动：巡逻速度、最短/最长移动时间、停留时间、追踪速度及警觉移动时间。
- 警觉：前向视锥长度/角度、圆形半径、每0.1秒视觉/声音增长、每秒下降值。
- 扑击：触发范围、速度、时长、扣除探索秒数、减速时长/倍率和恢复时间。

保存到 `Game/content/enemies.json`。回到关卡页，将对应怪物卡片拖到街道；移动、删除布置与普通对象相同。怪物碰撞箱必须放得进该街道。默认变异老鼠128×32，主角32×64；视锥256、圆形128；常态走1～2秒停1秒，警觉追3秒停1秒；扑击扣5秒、2秒内速度×0.8，攻击后停2秒。警觉未感知目标时默认每秒下降25，降到0解除警觉，不能跨街道追踪。

### 物品编辑

“物品”页编辑名称、独立贴图、基础价格、不规则占位（8×8编辑区）、稀有度和交易类别。当前游戏的17种物品已登记在 `Game/content/items.json`，包括电脑、补给、材料、汽车零件及旧原型的工业控制器。

保存后，游戏的物品名称、贴图、占格、旋转与交易价格从目录读取；已有站点报价保留其相对倍率。调整占格会参与存档的布局校验，修改后应检查已有物品能否继续放置。电脑仍保留可收纳、摆放为家具时朝向复原的行为。

### 建筑、柜子与加权物资

“建筑”页编辑可复用素材的宽度、楼层、贴图、墙色和局部碰撞箱。贴图可导入或从临时素材库选择，也可“移除建筑贴图”恢复程序绘制。碰撞箱以建筑局部坐标定义；当前横版移动使用横向碰撞范围。

柜子作为建筑的附带生成点编辑：

1. 点“＋柜子点位”，在预览中拖动柜子调整位置与楼层；“－柜子点位”移除选中点。
2. 设置点位 ID、相对建筑横坐标、楼层、每次抽取生成概率（0～1）和抽取次数。
3. 从物品卡片点击添加，或拖到预览中加入选中柜子的掉落候选。输入各项权重，使用“－移除”删除候选；至少保留一项正权重。
4. 例如概率0.8、抽取2次、水权重9/手册权重1：每次独立以80%概率生成，再按9:1选择物品。固定站点、日期和点位使用相同种子，关闭/重开柜子不会重抽。
5. 保存建筑素材后可拖入关卡。只想改某个已摆放建筑时，在关卡点击该建筑，再点“编辑此建筑 · 贴图/碰撞/柜子”；保存后返回关卡并保存关卡。

建筑素材修改影响后续拖入的实例；已有建筑保留自身配置。新实例不会继承旧物资槽的迁移编号。旧关卡散落物资已迁入建筑柜子，并保留旧槽编号以兼容已领取记录；底层展开成物资槽供原背包规则使用，现在支持独立室外生成点和建筑附属的散落物资，详见文末。

## 7. 存档与生效时机

客户数据保存后，新订单读取最新定义；新增头像在顾客入场时刷新。已生成订单保留身份、预算及进度。关卡数据在重新进入探索时加载，编辑器画布中的变化不会立即改变当前运行的地图。

存档版本16新增主动位，并记录好感、阵营信任、事件完成日期、未结束对话、当日到访 ID 和效果执行凭据，日结保留关系与已完成事件。兼容1～15版；14版及以前未保留已离场顾客身份，迁移时只能恢复仍在订单中的角色，后续到访完整记录。

内容保存与游戏存档是两件事：编辑器保存修改工程定义；游戏仍通过床铺结算保存玩家进度。不要在已使用的角色或故事上随意改 ID，以免断开已有关系或事件引用。

## 8. 故障排查

| 现象 | 检查方式 |
| --- | --- |
| 没找到保存按钮 | 使用右下固定保存按钮，看状态栏是否显示成功 |
| 新角色未显示 | 确认保存成功、贴图存在、已启用且参加交易、权重大于0、买卖类别有效；角色当天已到访则需下一天 |
| 贴图预览空白 | PNG 不得完全透明；资源路径须在所选 Game 工程内 |
| 对话未出现 | 核对互动场景、全部条件、前置事件是否完成及天数、是否已完成一次性故事 |
| 地图修改未出现 | 先应用对象属性并保存，再重新进入该站探索；确认站点登记成功 |
| Godot 连接失败 | 填引擎可执行文件而非工程文件/文件夹，检查版本与启动日志 |
| 端口被占用 | 用 `--port` 更换端口，再打开对应地址 |
| 编辑令牌无效 | 服务重启后刷新网页；先保留未保存的编辑内容 |

## 9. 数据接口与代码位置

服务仅监听本机回环地址。GET `/api/project` 返回客户、站点、登记、设置和本次服务的 token；写入请求携带 `X-Editor-Token`。

| 接口 | 内容 |
| --- | --- |
| GET `/api/level?station=<站名>` | 读取站点地图和邮电模板 |
| POST `/api/customer` | 保存客户/NPC 定义 |
| POST `/api/level` | `{station, definition}`，保存关卡并生成场景 |
| POST `/api/building-template` | 保存建筑素材、贴图/碰撞和柜子权重 |
| POST `/api/enemy` / `/api/item` | 保存怪物/物品定义 |
| POST `/api/catalog/archive` | 归档或恢复稳定ID条目 |
| POST `/api/content-image` | 导入怪物、物品或建筑的PNG |
| POST `/api/upload` | `{id, data}`，导入 base64 PNG |
| POST `/api/settings` | `{godot_executable}`，保存本机路径 |
| POST `/api/godot` | action 为 probe/editor/game/preview，preview 另带 station |

`server.py` 负责接口、校验和写入；`index.html`、`style.css` 定义页面，`editor.js`、`enhancements.js` 保留通用表单/关系设置，`workspace.js` 管理地图、素材拖放、线路图及对话视窗，`catalogs.js` 提供怪物/物品/建筑编辑，`geometry_editor.js` 负责不规则格、手动贴图绑定、楼层和掉落路径编辑，`models.js` 封装建筑实例与单次见面对话，`save_sessions.js` 集中管理编辑项草稿、保存边界、离开提示和桌面关闭握手。游戏由 `scripts/content/content_registry.gd` 读取关卡，`scripts/commerce/customer_catalog.gd` 读取角色，`customer_dialogue.gd` 管理关系和事件，`scripts/content/npc_interaction.gd` 提供探索对话窗口。

自动检查和浏览器交互验证统一见 [测试 README](../../test/README.md)。

## 散落物资、室外点与主动效果

关卡对象栏增加“物资生成点”，拖到任意实际存在的街道格上即可放置；不需要所属建筑。选中后点击“编辑物资类型与权重”，选择“柜子 / 散落物资”，设置生成概率、抽取次数，并用物品卡增减候选和权重。点击“保存条目”返回地图后，仍需“保存关卡”；选中地图对象可直接拖动或删除。

建筑的生成点也可选“散落物资”，勾选“建筑外（地面）”后在该建筑所在街道生成。附属点横坐标相对建筑，独立室外点是地图绝对横坐标。生成点支持同一位置多次抽取，散落物资逐件领取。建筑光照0～1，达到0.6会自动关闭玩家手电；暗处拾取无需开灯。

物品编辑新增主动效果：无主动效果、饮水、进食、治疗；治疗可指定恢复生命数值。游戏探索中在背包选择物品并装入右上主动位，空格使用；材料保留“无主动效果”，按空格不会误消耗。主动位物品独立保存，不计入背包占格。

## 地图网格、交易权重与物品占位

- 地图页：`Ctrl+Z`（macOS 为 `⌘Z`）撤销地图操作，点击工具栏或画布重绘后仍生效；在输入框中保留文字撤销。单纯选中对象不占用撤销记录。
- 线路层：“线路网格”控制显示，“网格吸附”独立控制新建站点、插入/追加折点及结点拖动的吸附。边长可设为 2～500 地图单位，不会强制移动已有结点，不影响贴图层。
- 顾客页：展开购买/出售类别，设置具体物品的权重；0 表示不参与，正数越大越容易出现。权重保存在 `buy_item_weights` / `sell_item_weights` 中，卖方数量保存在 `sell_item_counts[类别][物品ID] = {min,max}`，按类别映射到物品 ID 和权重。已配置类别每次订单按权重抽取3次，卖方具体条目可编辑“最少/最多”库存数量（0～100，支持固定值或区间；默认2～2）；每件商品数量独立按存档、站点、日期和订单确定，重复打开不会重抽，买方显示本次需求。未配置类别保留旧版整类买卖；归档物品不参与新订单。
- 物品页：先点“添加格子”或“删除格子”，再在 8×8 网格内拖拽框选，一次增删所选格子；至少保留一格。支持 L 形、空洞和分离格，运行时按真实格子判定碰撞。预览中的贴图可拖动、缩放和旋转，绑定保存在 `texture_binding`；调整格子不会自动缩放贴图。未绑定的新贴图初始按32像素/格显示，之后由编辑者调整。旋转/镜像预览会一起变换占位与贴图，不改变默认朝向。
- 游戏内：选中储物格物品后按 `F` 镜像，按 `R` 或滚轮旋转，放置后提交方向。镜像同步变换占位形状，不改变格子总数、价格或功能，会随背包、柜子和主动位保存；旧存档默认不镜像。电脑作为家具摆放时仍恢复正常朝向。

## 建筑贴图层、物理层与线状掉落区域

建筑编辑顶部可切换“贴图层 / 物理层”，预览始终合成显示贴图、碰撞箱、地板和物资区域。贴图层可以拖动、等比例缩放、旋转贴图；角上的方块为缩放柄，上方圆点为旋转柄，也可输入绑定位置、宽高、角度。物理层可以拖动碰撞箱、其右上角缩放柄及每层地板线。

点“添加楼层 / 减少楼层”维护1～8层。点层编号后可减少该层；各层地板高度可输入或直接拖动，单位为相对建筑底部向上的地图像素，高度逐层递增且间距至少24。删除楼层会将相应物资归到相邻层。数据以 `floor_positions` 保存；旧建筑未设置时继续采用原先的等距楼层。

选择物资点后，可切换“固定点 / 直线掉落区域 / 弧线掉落区域”。在物理层拖动端点改变区域位置和长度，拖动弧线中间控制点调整弯曲程度。位置相对建筑横坐标与该层地板高度；区域内每次抽取沿线长随机生成位置，再按原有概率与物品权重生成内容。散落物资逐件采样；柜子的多件内容共用同一柜子位置。同一天、同一存档重新进入时位置保持一致。区域保存在物资点的 `region` 字段，包含 `type`、`start`、`end` 和弧线的 `control`。

模板放入关卡后，仍需“保存关卡”；贴图绑定、楼层位置与掉落区域会随建筑实例保存到游戏，不通过普通文本属性框修改数组或对象。

## 物品 ID、展示缩放与存档维护

物品 ID 可以直接编辑。输入时自动查重，保存时服务端再次检查，归档物品及历史 ID 也占用名称。改名保留 `runtime_id` 与 `aliases`，已有存档、掉落、订单及内置规则继续识别旧 ID；不要手工删除这些映射。新 ID 以小写英文开头，长度1～64，可含数字、下划线及短横线。

预览上方“展示放大 / 展示缩小”及滚轮只改变视图，范围25%～800%，不会修改占位或贴图绑定。中键/右键拖动可平移，“重置视图”回到100%。放大后仍可准确拖动贴图控制柄。

### 编辑物品后旧存档无法读取

“无法读取”不一定是 JSON 损坏：物品占位增大、形状改变，可能使旧摆放重叠或越界；删除定义、改交易类别也可能使引用失效。

1. 在存档页点击“尝试修复”，确认“备份并修复”。工具先校验核心进度，再尝试重新整理背包和柜子，不丢弃物品；失效的当前订单会清理，已结算账目保留。
2. 成功前会生成同目录的 `.repair-backup-日期.json` 原文件备份。修复成功后点击“读取存档”。
3. 如果空间不足或缺少物品定义，修复停止并保留原文件。可先恢复编辑前的 `Game/content/items.json`（建议在项目副本中尝试），或恢复所缺物品和旧 ID 映射后重试。实际 JSON 破损或资金/家具核心字段异常不会被忽略，需要使用已有备份或匹配版本。

普通读取仍保持严格校验，不会静默删除物品或覆盖失败的存档。测试前可从 Godot“项目 → 打开用户数据文件夹”找到并备份 `saves` 文件夹。旧单存档 `Game/saves/cabin_slot.json` 也提供修复入口。

每个已占用存档栏位均有“删除”按钮，点击后出现二次确认；取消不修改文件。确认后栏位清空，文件移入 `saves/deleted`，可手动恢复到原栏位文件名。删除不会影响其他栏位。

## 家具编辑

顶部“家具”页管理 `Game/content/furniture.json`。选中家具或新建条目后，可连续编辑，最后用右下红色“保存草稿”统一保存；离开未保存条目仍有保存/放弃/取消提示。

1. **贴图与2D动画**：选择PNG、PNG二维帧表，或导入GIF自动转换帧表。家具贴图不再自动适配占位格：在预览中选择“拖动家具贴图 / 缩放家具贴图 / 旋转家具贴图”，拖动图片或白色角点、圆形旋转柄；也可直接填写绑定值。Shift旋转按15°吸附，滚轮缩放视图，中键或右键拖动画面。修改墙面/实物占位不改变绑定；新贴图按32源像素/格初始显示。建筑部分维持原有适配与编辑方式。动画可设置总帧数、帧表列数和fps，GIF保留逐帧时长；右侧预览循环播放。PNG动画各帧需同尺寸，空格补齐最后一行。
2. **占位格**：只使用一张三态网格，单击格子依次轮换“空置 → 实物 → 墙面 → 空置”；拖拽将选区全部设为起点的下一个状态，右键拖拽清空。每格只保存一个状态，不再切换两套占位掩码。不同家具的实物格与墙面格允许前后重叠；实物家具显示在墙面家具前方。勾选“悬挂物”后，单击切换空置/白色参考格；取消后恢复空置/实物/墙面三态编辑。参考格不构成占用或挂点容量，挂点仅允许一件悬挂物，贴图中心直接对齐挂点。
3. **互动与储物**：选择睡觉、电脑、出站、交易、整备、通用储物等功能；勾选储物后设置默认宽高。游戏内装修可覆盖具体家具的储物尺寸，缩小前会检查已有内容。实物格上边缘直接提供承托，混合家具的墙面格负责固定、实物格承托其他家具，无需额外支撑开关。
4. **物品/家具双重属性**：选择关联物品，保存后该物品同时具有家具属性。背包使用原物品贴图，摆放/装修使用家具贴图；收纳旋转不会改变摆放朝向。请先在物品页创建对应物品。
5. **需求/排斥距离**：添加规则，选择目标家具或效果标签，填写家具格距离。需求为必须存在邻近目标，排斥为最小间隔；只计算同一车厢的最近实际占位格，空洞和外框不计入；相邻格距离0，隔一整格距离1。预备仓库默认规则为“需求门，距离6”，可以直接调整。效果标签例如 `light` 可由任意家具提供。

新建的非物品家具若勾选“基地拥有此家具”，会作为新基地已有家具，未放置者进入临时收纳，必须放置后才能完成装修。编辑默认定义后重新运行游戏读取；已存在的家具位置和各存档的储物尺寸分别保存在存档内。规则或占位改变后，装修检查会提示需要调整的布局。

### 建造配方与预览辅助层

家具页可设置“已知家具”、所需技术（技术ID和等级）、建造材料、分解消耗及分解返还。技术ID `auto_repair` 读取汽修等级，其他ID读取存档技术表。新条目默认已知且不要求技术，材料配方可独立添加/删除物品与数量。游戏建造列表显示每项条件，全部满足的条目置顶、按家具ID字母顺序排列。

物品、家具和建筑预览统一先绘制贴图，再绘制占位格/碰撞箱。在预览上方取消“显示占位格”或“显示碰撞箱”可查看完整素材；隐藏碰撞箱同时隐藏建筑地板辅助线。这些开关只影响视图，不修改数据或产生未保存状态。隐藏的碰撞箱/楼层不能被误拖动，贴图绑定和物资区域编辑仍可使用。

悬挂物的贴图仍可缩放和旋转；白色参考格用于估计实机尺寸，不会随参考格数量自动适配贴图。切换悬挂属性时格子形状转换为参考格或实物格，不同时保留两种模式。绑定中的横纵偏移用于调整预览里参考格与贴图的关系，游戏安装时仍以贴图中心对齐挂点。

三态网格以 `occupancy_grid` 保存，行对应纵坐标、列对应横坐标，值只允许0/1/2。服务端和游戏兼容旧数组格式；保存后只保留矩阵。网格宽高可扩展，缩小时先清空超出范围的格子；至少保留一格实物或墙面。参考格不参与物理、距离或挂点容量判定。
