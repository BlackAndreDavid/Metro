# 客户编辑与关卡编辑拓展部件

这是放在 `tools/` 的本地可视化工具，两个页签共用一个启动入口。游戏工程位于 `Game/`。工具不需要安装进 Godot 的 addons，也不会修改第三方插件。

## 启动

需要 Python 3.10+、Pillow 和现代浏览器：

```sh
python -m pip install -r tools/editors/requirements.txt
python tools/editors/server.py
```

默认自动打开 `http://127.0.0.1:8765`。Windows 也可双击 `tools/editors/启动内容编辑器.cmd`。端口占用时使用 `--port 8766`；不自动打开浏览器用 `--no-browser`。服务仅监听本机回环地址，不需要账户或云服务。

可用 `--project /absolute/path/to/Game` 编辑另一份工程。按 Ctrl+C 关闭服务。选择文件、拖动节点和改属性只修改编辑区，点击保存才写入工程；离开页面前记得保存。

## 客户编辑器

1. 选择已有顾客或点击“新增顾客”。顾客 ID 创建后保持不变，目录按追加方式保存，避免旧存档的角色索引错位；不再使用的角色可停用或把权重设为0。
2. 设置名称、基础预算、出现权重和买卖类别。方向以顾客为准：“购买”表示从玩家买，“出售”表示卖给玩家。
3. 出现权重在当前站点、买卖方向的有效候选中归一化：权重1、3的两个候选概率分别为25%、75%；权重0或停用不出现。基础预算直接作为新订单预算，现有订单保留原预算。
4. 上传 PNG 或填写已有 `res://assets/...png` 路径。上传保留独立原图，并生成独立的48×80透明运行图；只进行最近邻缩放与对齐，不擅自改变配色。客户窗口显示上半身，原全身素材保留供后续拓展。
5. 保存后，新订单读取最新定义；关闭再进入交易即可刷新新素材，不需要手工编辑 GDScript。已到访但未结束的顾客不会因编辑而重抽。

客户数据：`Game/content/customers.json`。图片分别写入 `Game/assets/source/customers/` 和 `Game/assets/textures/customers/`，每位独立保存。

### 条件剧情与分支图

- 点击“新增剧情”，设置唯一剧情 ID、标题、优先级、仅触发一次和触发条件。
- 通过“新增节点”创建文本节点；点击图中的节点编辑说话人、文本、进入时设置的标记及分支。节点可拖动调整图上位置；位置不影响游戏逻辑。
- “添加分支”可编辑玩家选项、目标节点和该分支的可见条件。目标“结束”表示结束这段剧情。没有可见分支时走默认后续节点，未设置后续则结束。
- 金色起点标识表示剧情开始节点；“设为起点”“重命名”“删除节点”会同步更新引用。没有出口的循环和不存在的分支目标会在保存时拒绝。
- 顾客到达窗口后，先检查剧情条件。满足时显示对话、禁止交易确认；多个剧情按优先级从高到低处理。剧情结束后恢复订单，也可在剧情中“送客”。
- 单次剧情的完成标记、节点标记及未结束的对话节点随游戏状态存档；再次进入同一订单可继续对话，不会重复付款或重置预算。

触发条件和分支条件都是 JSON 对象，所有字段按“并且”组合；`{}` 表示无条件。例如：

```json
{
  "stations": ["邮电新村", "四平路"],
  "day_min": 2,
  "account_min": 20,
  "completed_min": 1,
  "has_items": {"water": 1},
  "flags_none": ["old_man_helped"]
}
```

支持 `day_min/day_max`、`account_min/account_max`、`debt_min/debt_max`、`completed_min`（当前站当天成交数）、`stations`、`has_items`（背包+柜子）、`flags_all/flags_none`、`blackout`。进入节点时可填写逗号分隔标记，供之后的分支和剧情使用。预置拾荒老人的第二天问候剧情可作为参考。

## 关卡编辑器

1. 切到“站点与关卡”，从游戏已有74个站点中选择目标站。
2. 没有探索场景的站点可点击“从邮电新村模板新建”。模板保留现有三街道玩法与绘制结构，不创建另一套移动或背包系统。
3. 修改街区名称、分段宽度、地面和层高，以及三条街道的分段名称。地图支持三条街道、每条1–8个分段；建筑支持1–2层，对应现有楼梯逻辑。
4. 点击地图选对象并横向拖动，或选择对象类型和条目，通过属性表编辑建筑、站点入口、巷口、物资点、汽车。点击“应用对象属性”刷新预览。
5. 建筑 ID、位置、街道及楼层修改时会同步调整所属物资；删除建筑会删除其内部物资，避免悬空引用。物资 `kind` 留空沿用原掉落，指定合法物品 ID 可固定掉落。
6. 点击“保存并生成场景”。工具先校验边界、唯一 ID、建筑与物资引用、楼层和入口，再生成：
   - `Game/content/levels/station_<hash>.json`：地图配置；
   - `Game/scenes/exploration/stations/station_<hash>.tscn`：继承现有 `exploration.tscn` 的场景；
   - `Game/content/registry.json`：站点与场景的对应关系。
7. 在游戏中前往该站，重新出站探索即可加载。场景布局仍可在 Godot 中编辑；建筑、物资和拓扑由 JSON 驱动，小地图与互动同步使用相同数据。

邮电新村、四平路、同济大学默认共用 `content/levels/postal.json`；在工具中保存某个站，会为其生成独立配置，不覆盖邮电模板。其他未登记站点继续原简化探索流程。自定义关卡汽车 ID 自动加关卡前缀，避免不同站点的拆车记录互相影响。

## 与“打开编辑器.cmd”的区别

`Game/打开编辑器.cmd` 启动的是 **Godot 工程编辑器**，用于编辑 `.tscn`、脚本和运行游戏；这里的启动器启动的是 **内容编辑网页**，用于作者编排客户、剧情与关卡数据。两者操作同一份 Game 工程，可以配合使用。

## 验证

```sh
python test/tools/run_tests.py --godot /path/to/Godot_v4.7.2-stable_linux.x86_64
```

测试覆盖：编辑 API、输入校验、分支引用、场景导出，以及在隔离的完整 Game 副本中实际加载新客户、剧情、存档节点和新站点探索。测试不会把临时客户或站点保存进正在编辑的工程。

可选网页实际交互检查（需 Playwright 和 Chromium）：`python test/tools/check_editors_browser.py`。它会在临时项目里新增客户、上传贴图、编辑分支、拖动地图对象并保存场景，截图输出到 test/results/editor-ui，不改变当前工程内容。
